## Implemented

- Whole-item Euler rotation defaults to 30 degrees on all devices. Desktop keeps 100 CSS px rings and Shift free rotation. Touch/Pencil use separate, fixed screen-space XYZ controls, not enlarged overlapping rings. Pointer/axis ownership is held through the gesture; preview is transient, release is one history transaction, cancel writes nothing.
- Whole-item manipulation uses a fixed basis: single flat center, two-panel seam midpoint, three-panel middle-panel reference center. Folding does not recompute a moving bounds-center pivot. Hinge increments remain separate.
- New platform and sleeper library drafts stand on their long edge; thumbnails and existing placements are unchanged.
- Horizontal native dragging retains the source elevation rather than ray-hit surface height. Explicit Y movement/stack proposals choose elevation. Rotated/folded model bounds constrain the stage floor; legacy invalid saved poses are not silently migrated.
- Exact geometric contact is distinguished from positive penetration using a small numerical interior tolerance. Touching objects and stage floor have a visible zero-gap label. Overlap feedback identifies actual object overlap, floor penetration, or a preview conflict. “Confirm placement” is a session acknowledgement, never a collision override.
- Camera controls stop during object interaction; explicit stage-view lock also blocks camera navigation keys. Front-compass reset uses a nearby audience position; other compass paths are unchanged.
- Fold pointer updates are coalesced to one preview per animation frame, final angle flushed on release, cancelled work discarded. No GLB hierarchy changes.
- Dia minimizes only to a 24 × 40 CSS px right-edge chevron, vertically draggable outside mode controls. No left/right docking labels. Touch composer is 20 px text / 112 px height and accommodates focus without the old pinned-preview rule shrinking it.
- Compact library selection row, narrower stage sidebar minimum, grid/contact controls next to the bottom-left compass. Existing palette, typography families, corner treatment, icon language and motion retained.
- Two explicitly requested flats can preview a separated partial enclosure with a measured opening. No fabricated third flat, no claim of a complete U. Existing deterministic layout validation, Ghost, Accept/Cancel and history remain authoritative.
- Existing OpenAI path now has a read-only Chinese dialogue reply alongside validated structured grounding. Ordinary conversation and explanations do not create actions or Scene writes. Supported placements still require deterministic resolution and human confirmation.

## Language correction tuple

Old assumption: every “enclose a space” request requires three flats.
Correction: explicit “two” is binding; provide an incomplete two-flat alternative with an opening, explain the limitation, never silently add a third.

General rule: preserve explicit quantity and geometry feasibility independently. Semantic interpretation does not choose XYZ or bypass validation.

Positive:
1. 用两个景片围一个空间，中间留个入口。
2. 两块景片围空间，留一个入口。

Paraphrase: 拿二片景片围一下，中间留个入口。

Contrast:
1. 三块景片围一个空间 — retain the full three-flat U path.
2. 两块景片拼成直墙 — align edges, do not infer an enclosure.

Ambiguous: 两块景片围得开放一点 — clarify the requested opening; do not invent dimensions.

No Knowledge concept activation, canonical camera eval edits, or theoretical blocking/focus execution was added.
