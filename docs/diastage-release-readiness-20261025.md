# DiaStage 腾讯云上线前准备清单

整理日期：2026-10-25。本文记录当前验收版的准备情况、上线前工作和需要用户决定的事项，不执行部署。

Windows 本机能够启动、登录和编辑，不等于腾讯云已经运行同一版本。本文没有连接服务器，也没有读取真实环境密钥、账号数据库或剧目内容。

旧文档中的服务器、DNS、防火墙、证书和数据库统计来自 **2026-10-22**，是历史记录，不能当作当前云端现状；发布前必须重新核对。特别不能沿用当时“云端没有剧目”的判断直接覆盖或初始化数据库。

## 已准备

1. **当前验收版和 21 件可选道具。** 舞台库、照片匹配及新生成候选均为 21 件。单帘景片 `SCN-FLAT-090` 不再供新选择；底层资源和历史注册保留，旧剧目仍可读取和调整。照片示例的墙体按原尺寸保留为可编辑构件。

2. **本地测试和构建记录。** 2026-10-23 最终验收为 **3709 项通过、1 项跳过、0 项失败**，其中全应用回归为 1204 项通过；类型检查和生产构建通过。跳过项是既有材质测试。上述记录属于本地及隔离 QA，不代表 Linux、云端账号或真实付费 AI 已经验收。

3. **资源和已修复问题。** 模型、缩略图、预览图及静态资源已做本地存在性和 HTTP 检查；Basis、Draco 解码器已本地化。已修复渲染器销毁后的晚帧和本地视角成功后残留服务错误提示的问题。真实手机、麦克风权限及付费模型仍需分别验收。

4. **部署模板和操作说明。** 仓库已有 `deploy/nginx-http.conf`、`deploy/nginx-https.conf`、`deploy/diastage.override.conf`、`deploy/production.env.example`、Docker 配置和发布说明。既有方案沿用 Node、Nginx、systemd；没有必要仅为此次更新改用 Docker。模板存在不表示已安装到云端。

## 待完成

5. **重新整理最新源码发布包。** 以本次验收版的明确提交为准，记录提交号和包的 SHA-256。检查上传内容，排除真实环境文件、账号和场景数据库、密钥、预算账本、备份、日志、测试数据、`node_modules` 和 Windows 构建产物。`.gitignore`、`.dockerignore` 已有基础排除，仍需核对实际包内容；私有迁移数据不得进入 GitHub 或公开镜像。

6. **在目标 Linux 环境构建。** 核对 Node.js 22.13 或更新版本，以及 `node:sqlite`、SQLite 备份 API；使用仓库锁定的 Bun 1.3.14 安装依赖。构建在新发布目录和隔离数据目录完成，认证服务由 Node 运行。不要把 Windows 本机的 `.next`、原生依赖或开发服务直接当作云端生产版本。

7. **复核域名和防火墙。** 确认根域名、www 的解析和实际部署目标一致；核对云端及操作系统防火墙的 80、443 端口。应用端口只供服务器内部反向代理使用，不直接向公网开放。此项重新确认后才能把历史记录标为当前有效。

8. **完成 HTTPS 和反向代理验收。** 证书覆盖根域名和 www，配置 HTTP、www 到唯一 HTTPS 入口的跳转，并验证自动续期。核对 Nginx 转发的 Host、协议和客户端地址；保留 SSE 所需的关闭缓冲及长连接设置。真实服务器配置应先通过 `nginx -t`，再切换。

9. **准备私有生产配置。** `BETTER_AUTH_URL` 必须与正式 HTTPS 入口完全一致；在服务器私有环境中设置稳定的、至少 32 字符的 `BETTER_AUTH_SECRET`。更新时保留既有有效密钥，不将其写入客户端公开变量、源码、日志或本文。`MINT_PASCAL_HOST_ORIGIN` 等旧变量不能替代认证入口配置。

10. **固定全部持久数据路径。** 核对既有云端真实目录，保持数据与发布目录分离。`PASCAL_DB_PATH` 优先于 `PASCAL_DATA_DIR`；`auth.sqlite` 自动放在场景数据库同目录，不能只迁移其中一份。另行设置 `DIASTAGE_AI_LEDGER_PATH` 为持久目录中的绝对路径：它默认解析工作目录下的 `data/ai-usage.db`，不会跟随场景数据库，换发布目录可能使预算从空账本开始。

11. **按单实例 SQLite 运行。** 初期保持一个应用进程、一个明确的持久数据源，并确认服务账号有读写权限。配对、部分任务和限流状态保存在进程内；不要未经改造就增加多个 Node worker、容器副本或负载均衡实例。多实例、共享状态和数据库扩容另列后续工作。

12. **准备备份、恢复和回滚。** 在发布或迁移前对场景库、认证库、预算账本及对应私有设置做一致性备份，正确处理 WAL 中的数据；同时保存原服务、Nginx 和环境配置。备份放在私有位置，实际验证可恢复。保留旧发布目录；若新版本已经产生数据，回滚前先另存新数据，不能直接用旧库覆盖。

13. **列出云端正式验收。** 使用正式域名检查首页、21 件道具、资源解码、注册或迁移账号登录、退出、自己的剧目读取和保存、其他账号隔离、重启后数据留存。检查浏览器错误、代理长连接和服务日志。`/api/health` 成功只表示进程存活，匿名 `/api/auth/get-session` 返回空会话也不能证明完整登录流程通过。

14. **补齐 AI 接口和预算配置。** 若首发开放 AI，服务端需配置 API Key、可达的供应商接口、模型权限和额度，分别验证复杂口令、语音转写、剧本及照片功能。当前代码的价格映射只识别 `gpt-5.6-luna`、`gpt-5.6-terra` 文本和 `gpt-transcribe` 转写；更换模型还需同步预算映射，不能只改环境变量。核定单次软限额、剧本硬限额、月额度及参考汇率；目前月预算按整张账本汇总，是全站共享限制，不是按账号分别计费。模拟服务通过不能替代真实接口验收。

15. **明确账号恢复和邮件能力。** 当前普通认证没有接入 SMTP、邮箱验证或公开找回密码邮件；只填邮件环境变量不会自动补齐发送实现。开放公众注册前需确定恢复流程，并如实说明功能边界。旧剧目归属迁移使用精确 ID 和预检查流程，不能按邮箱自动认领，更不能批量归给新注册账号。

16. **复核公开页面与服务说明。** 检查备案展示、隐私说明、联系和问题反馈入口、注册及收费说明与实际服务一致；说明启用 AI 时哪些文字、语音或照片会发送到服务商。备案及公安联网备案状态和后续要求由实际运营方按官方信息核实，不使用历史控制台状态或未取得的编号代替当前结果。

## 待用户决定

17. **本机数据是否迁往云端。** 选择“云端独立新开始”或“迁移指定本机账号和剧目”。复制源码不会带来账号和剧目；即使使用同一邮箱重新注册，新的用户 ID 也不会自动匹配旧场景的 `owner_id`。如需迁移，应先确定源库、目标库、数据归属和备份方案，私密转移账号与场景数据，保留 ID 对应关系，并单独确认认证密钥策略。云端和本机来源不同，登录通常需要重新进行。浏览器中的未同步 Journal、对话、草稿及 `asset://` 素材不随服务器数据库自动迁移，应先导出或补齐。

18. **首发开放范围和费用责任。** 可以先开放手动置景、明确本地口令、21 件资产和已有场景功能，待服务配置与真实验收完成后再开放付费 AI。确定是否允许公开注册、由谁承担 AI 费用，以及全站共享预算是否适合预期用户量。手机配对、扫描、视频动画、灯光制作及专业排演分别按功能开关和验收结果决定，不能把当前未开放能力写成已上线。

19. **素材公开授权。** 确认舞台道具、示例照片、用户上传内容等允许在公网展示和使用。现有道具来源记录保留了内部资料和版权提示，不能将“本机可以查看”当作“允许公开发布”。未确认的素材应先处理授权或调整发布范围。
