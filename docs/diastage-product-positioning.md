# DiaStage 咫台 · 网站定位

更新：2026-10-28。依据用户已确认的产品方向与当前应用源码 `232b26e` 整理。本文件区分产品定位、现有能力与待验收目标；GitHub 同步和本机启动不等于正式域名发布。后续进度以[上线待办](diastage-release-todo.md)为准。

## 一句话定位

**DiaStage 咫台是面向戏剧创作与排练的网页空间辅助工具，以21件标准道具为基础，把文字想法、剧场照片和剧本中的场景布置转成可预览、可调整、可保存的三维排练方案。** 11月1日版本聚焦AI置景、照片置景和剧本置景，复台入口隐藏。

核心价值是让创作者在有限场地和常见道具条件下，把空间关系讲清楚、摆出来，再带着方案去排练。照片中的具体物件可以由相似道具代替，重点是位置、朝向、体量、高低关系、遮挡和通道。

品牌主标题延续：**把戏说给 Dia。** 配套说明建议：**先在咫台摆一遍，再到排练场试一遍。**

## 面向谁、解决什么

| 使用者 | 要解决的具体问题 | 咫台提供的工作方式 |
| --- | --- | --- |
| 导演、编导与排练负责人 | 想法停留在口头，家具与人物活动空间难以说清 | 围绕同一空间预览讨论布景，再调整位置与朝向 |
| 舞台监督、舞美与道具执行人员 | 照片中的舞美无法直接搬进排练室 | 用现有标准资产做替身，明确原物与替身的对应关系 |
| 戏剧院校、学生剧组与小型剧团 | 缺少专业建模经验，排练场与道具有限 | 从舞台尺寸、常用道具、照片或剧本文字开始布置 |
| 复排团队 | 原排练方案需要再次取用和调整 | 保留可编辑剧目与版本；跨场地复台映射是后续方向，11月1日版隐藏入口 |

这里描述的是产品面向的工作场景。当前剧目按个人账号私有保存，不代表已提供多人同时编辑、团队权限或共享项目空间。

## 招牌功能：标准道具的排练转译

### 照片 → 排练布景

识别照片里可见的布景和相对空间，再映射到现有21件资产。例：钢琴可用三屉桌、扶手椅可用短沙发作排练替身；窗区应优先识别和匹配窗景片，保留窗框与洞口。

所有新照片方案使用目录资产原尺寸、原比例，允许移动、转向和资产自身支持的开合；需要大台面时组合足量标准台块。禁止为迎合透视而把圆桌压成椭圆、随意拉长景片或生成库外专业模型。替身应明确命名，便于实际排练。这是自动照片方案的约束；手工编辑仍保留既有尺寸/整体缩放能力。

单张照片不能直接给出可信的实测尺寸和遮挡处结构。先以用户场地尺寸为边界；没有尺寸时明确标为暂定，保留少量、简短的核对项。效果图、灯光、材质装饰和人物建模不属于当前招牌功能范围。

### 剧本 → 场景布置

从剧本文字提取场地、布景、道具及有依据的空间关系，提出可编辑的置景方案。目标是理解既有剧本里的场景，不是创作新剧情、续写对白或生成新剧本。

当前附件路径支持文字型PDF；扫描版PDF的OCR尚不在已支持范围。原始PDF不持久保存，仅保留用户采纳的相关片段。需要模型理解时会处理本次所需的提取文字和注解；“不保存PDF”不等于没有第三方模型处理。

### Dia 对话 → 布置提案

Dia 位于舞台编辑环境中，围绕当前场景、可用资产和用户意图提出布置建议。常见操作可以直接用文字表达，复杂描述交给真实模型理解；结果经过资产、坐标、几何与额度检查，再进入预览与确认。

二连、二联、三连、三联按现有折叠景片理解。房间式布景默认三面围合、朝观众开口；模块数量、活动空间或尺寸不够时应明确说明，不拉伸资产补齐。固定模板已有实现，任意尺寸的组合搭建仍须逐例验证。

### 额度与保存：支撑三种置景入口

手动置景、本地口令与保存不消耗模型额度。需调用模型的文字、照片和剧本分析共用同一账号额度，显示使用情况，额度不足时停止新的付费请求。

已确定的首轮安排是最多20个受邀账号、网站承担API费用，全站每月100元、每账号每日1元且每月5元；日额度计入月额度。这是内测预算规则，不是售价、充值套餐或长期免费承诺。注册不会自动获得AI名额。

| 类别 | 标准资产 | 数量 |

| 折叠景片 | 二帘组合、三帘组合 | 2 |
| 门窗景片 | 窗景片、落地窗景片、单门景片、双门景片 | 4 |
| 台块与基础件 | 一号台块、二号台块、三号台块、枕木、方墩 | 5 |
| 沙发 | 长沙发、短沙发 | 2 |
| 桌类 | 三屉桌、二屉桌、圆桌、特殊桌 | 4 |

21指可选资产种类，不是每个场景只能放21个物件。隐藏的旧单帘景片仍兼容历史场景，不计入新选择目录。尺寸、关节与实体检查依据见[布景拼接与空间规则](diastage-scenery-assembly-rules-20261027.md)。

## 使用流程与交互原则

1. 新建或打开自己的剧目，确定场地尺寸与观众方向。
2. 手动放入道具，或在Dia文字栏输入想法、拖入图片或文字型PDF。
3. 附件区保留文件名、可选注解和最多两行操作说明；点击发送后才开始解析。
4. 查看方案、替代关系与必要的短核对项，在舞台上试摆。
5. 检查位置、朝向、接缝、平台高度和通道，确认后采用并保存。
6. 后续继续调整或恢复剧目；照片方案以独立新场景承接，保留原剧目。

界面围绕“输入—预览—确认—调整”组织。AI、照片、剧本共用置景空间和Dia入口，不新增三套独立工作区。规则与检查服务于排练；实现细节、模型协议和调试记录留在开发文档。语音与复台入口在11月1日版隐藏，先完善文字与文件入口；已有复台数据和实现保留。

## 空间合理性的产品约定

- 有意拼接的景片和台块应贴合；家具周围、门口与演员通道仍需留空。
- 道具按实际外廓与折叠姿态检查，区分合法接触、围合空腔和实体穿透。
- 平台上的物件需有明确支撑关系，不能通过穿入台面或任意改高度掩盖错误。
- 移动、折叠与确认过程提供相关几何反馈；不承诺任何操作、任何姿态都绝无穿模。
- 软件预览用于空间辅助。实物承重、稳定性、紧固方式及现场通行须结合实际条件核对，不能由零碰撞直接推导安全。

## AI的角色与当前技术路线

咫台采用“真实大模型理解＋标准道具目录＋确定性几何检查＋人工确认”的组合。大模型承担语言、图片及文字场景理解；程序负责资产约束、数据格式、空间校验和执行边界。本地规则处理可明确判断的操作，不能把整个Dia描述为纯规则聊天，也不能把模型输出直接当作可落地结果。

本机验收目前接入阿里云百炼北京的 `qwen3.7-flash-2026-07-15`。真实请求已有返回证据，照片自动坐标及完整动作效果仍在验收。Plus保留为同样例比较路线，尚未完成权限和价格适配；暂不以其作为已启用能力宣传。

## 账号、素材与跨电脑使用

每个账号拥有自己的剧目与素材。已确定的保存范围包括场景使用的图片、扫描模型以及采纳的剧本片段，原始PDF不保存；其中“扫描模型”指已有模型的导入与保存范围，不代表网页或独立App已提供原生场地扫描。

素材同步代码按账号隔离，保存场景前上传所引用素材，新设备先恢复素材再加载场景。当前已完成定向与隔离测试，实际两台电脑的完整流程仍待验收，不应宣传为已验证的无缝协作。

剧目备份可恢复为独立新剧目。完整删除方式、数据与备份保留期限仍待确定，公开条款需按最终实现完善。
