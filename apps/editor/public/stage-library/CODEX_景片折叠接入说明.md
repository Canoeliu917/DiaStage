# 给Codex：二联、三联景片的折叠功能

## 用户看到的说法

像屏风一样，沿两块板的连接处折起来或展开。二联像一本书，有1处可以折；三联像三折屏风，有2处可以分别折。

界面入口统一叫“折叠景片”，控制点叫“折叠位置1”“折叠位置2”，数值叫“打开角度”。例如打开到90°形成直角，打开到180°铺成一条直线。用户帮助和操作提示不使用“铰接”“局部轴”“四元数”等开发术语。

“旋转整个道具”改变整组景片的朝向；“折叠景片”改变几块板之间的打开程度。下面的节点与坐标说明供Codex开发接入使用。

请将本说明作为22件置景道具接入任务的补充要求。用户确认二联、三联景片需要沿连接处折叠；整体移动、整体旋转与内部折叠是三种独立操作。

## 已有模型与待实现功能

两个GLB已经保留独立景片、铰接支点和父子层级。现有小图只是默认姿态的静态预览，不代表模型角度固定。无需重新建模；本次交付增加控制标注，应用内的控制点拖动、碰撞限制、历史记录和保存恢复仍需实现。

| 资源ID | 菜单名称 | 可调节点 | 状态字段 | 默认相邻夹角 |
|---|---|---|---|---|
| `SCN-FOLD-02` | 二帘组合（二联） | `Hinge_02` | `fold_angle_1_deg` | 90° |
| `SCN-FOLD-03` | 三帘组合（三联） | `Hinge_02` | `fold_angle_1_deg` | 90° |
| `SCN-FOLD-03` | 三帘组合（三联） | `Hinge_03` | `fold_angle_2_deg` | 90° |

`Hinge_01` 是首片及后续层级的根支点，不是另一个可调折叠关节。三联中 `Hinge_03` 是 `Hinge_02` 的子节点。

## 操作要求

1. 默认选中整件景片组合，用整体工具移动、旋转和摆放。门框、板面、横档等子网格跟随所属景片，不能在普通点击时散开选择。
2. 在选中组合的属性面板提供“折叠景片”入口。二联显示1个折叠位置，三联显示2个；控制点可放在连接竖边中部，旋转轴必须穿过已有铰接线。
3. 用户点击控制点后，用左键拖动角度控制柄，或输入夹角；显示当前角度。沿用项目旋转吸附增量，提供90°、180°等预设。
4. 二联调整 `Hinge_02` 时，首片保持，第二片转动。三联调整 `Hinge_02` 时，后两片一起跟随；调整 `Hinge_03` 时，前两片保持，末片转动。
5. 折叠模式不修改道具整体的position、rotation、scale。退出折叠模式后，仍以整个组合移动和摆放。
6. 相机环绕只改变观察方向。控制柄拖动期间暂停相机拖动；中键观察不改变折叠角度。键位沿用此前确认的UE5主布局及中键环绕扩展，折叠入口使用可见控件，不另行占用Ctrl或Q/E。

## 角度与坐标：按实际GLB绑定

UI和保存数据使用“相邻景片夹角”，单位为度：180°展开成一直线，90°为直角围合。模型声明的数学范围是0–180°。

**0°只是理想几何收拢值。现有模型有实体厚度，尚未实现厚度避碰、五金限位或无穿插闭合。** 接入时应检测移动景片与其他景片的碰撞并限制到有效角度；判定须排除正常铰接接触，并结合真实部件，不能用整个组合的外包围盒禁止正常围合。未做完时应明确标记该限制，不把0°写成已经验证的实物闭合状态。

当前0–180°、正向转轴定义描述同一折向；不要据此宣称已支持反向折叠、Z形反折或穿过相邻板面。若之后扩展双向折叠，应单独定义有符号折向、限位及碰撞行为。

原始Blender为Z向上，导出的GLB已经转换为Y向上。文件中关节的 `extras.control.kind = "rotation_z"` 沿用**源Blender坐标含义**；对于未再改基的GLB节点，实际铰接旋转轴是局部 **+Y**。

```text
相邻夹角 = angleDeg
GLB节点局部Y旋转 = (180 - angleDeg) × π / 180
180°展开 → 局部旋转0°
90°围合  → 局部旋转90°
```

以上是节点的绝对目标旋转，不是在文件已有90°姿态上再叠加一次90°。保留原节点的translation、scale和父子关系，仅根据角度更新该节点的局部旋转。

若渲染器使用未改基的GLB局部坐标，可用局部+Y轴与上式构建轴角四元数，并赋给目标关节。若导入层另做过坐标基转换，应通过同一转换适配关节轴和旋转，不能只改UI轴名称，也不能简单交换欧拉角。

## 实例、数据与保存

- 每个放置实例拥有自己的节点树与折叠状态。网格几何可以共享；可变的节点变换不能共享。修改A实例不得改变B实例或资源库默认姿态。
- 保留 `Hinge_01 → Hinge_02 → Hinge_03` 层级，以及各片自己的板面、框架和五金子节点。优化渲染时不能将跨关节的网格烘焙为单个不可动模型。
- 场景实例以 `assetId` 和独立 `instanceId` 识别，同时保存整体变换及下列 `controls`；恢复时先读取存储值，缺失字段才使用默认90°。
- 连续拖动只做预览，松开后提交一次历史事务。撤销、重做、取消拖动及失焦恢复需沿用项目现有规则。
- 折叠后重新计算实例的包围盒、占地、拾取与碰撞代理。资源清单里的 `bounds_m` 是默认姿态，不能作为所有折叠姿态的固定边界。

三联实例的部件状态示例（不是完整场景工程）：

```json
{
  "assetId": "SCN-FOLD-03",
  "instanceId": "由主应用生成唯一ID",
  "controls": {
    "fold_angle_1_deg": 90,
    "fold_angle_2_deg": 135
  }
}
```

更新后的 `prop-menu-manifest.json` 在两个资源上增加了 `articulation`，显式列出节点、父节点、状态字段、默认夹角、有效数学区间以及GLB局部轴转换。原GLB字节、模型尺寸、材质和已有资源ID保持一致。

| 三联只改变第2夹角 | 首片、中片保持，仅末片转动 |
| 相机环绕与整体旋转 | 不改写两个折叠状态字段 |
| 复制两个三联实例，折叠其中一个 | 另一个及资源默认姿态保持 |
| 保存、关闭、重新打开 | 整体姿态、两处夹角和资源ID一致 |
| 一次拖动、撤销、重做 | 各对应一次完整折叠事务 |
| 极限角度、取消、失焦 | 无持续拖动；碰撞与尚未实现的限位状态清楚 |
